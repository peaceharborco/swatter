# Swatter v2.0 — backends, multi-channel alerts, outbound feedback design

**Date:** 2026-06-17
**Status:** approved design, pre-implementation
**Scope:** one combined spec — pluggable direct-plane firewall backend (ipset),
multi-channel ops-critical alerts (local mail · SendGrid email · Twilio SMS ·
Slack/Discord/generic webhook), AbuseIPDB outbound reporting (opt-in), and
fleet ban-sync (export/import). Version → 2.0.0.

The guiding invariants are unchanged and paramount: **never take the site down**
(the CSF/direct plane is only ever used for offenders whose socket is the
attacker; the never-block allowlist is checked last and wins; fail-closed
disables direct denies when the CF range list is untrustworthy). Every new
outbound action (alert, AbuseIPDB report) is **best-effort** — it never blocks,
delays, or aborts a scan or a firewall decision. Every credentialed feature is
**opt-in and degrades to no-op** without its config; nothing here is required to
run.

---

## Part A — Pluggable direct-plane backend + ipset

### A.1 The abstraction — `lib/block.sh`

The scan loop currently calls `swatter_csf_temp`/`swatter_csf_perm` directly
(`score.sh:81-82`) and `swatter_csf_unblock` (`bin/swatter:140`). Introduce a
thin backend-agnostic router:

```
swatter_block_direct_temp    <ip> <ttl> <reason>
swatter_block_direct_perm    <ip> <reason>
swatter_block_direct_unblock <ip>
```

Each routes on `DIRECT_BACKEND` (default `csf`): `csf` → `swatter_csf_*`
(unchanged `block_csf.sh`); `ipset` → `swatter_ipset_*` (new `block_ipset.sh`).
The router is *thin* — no policy logic of its own. **`block_csf.sh` is NOT
modified**: the proven, safety-critical CSF path keeps its own dry-run check,
per-run cap, and counter exactly as today. `block_ipset.sh` mirrors that same
structure independently. (This deliberately duplicates ~6 lines of cap/dry-run
between the two backends; for the tool's cardinal "never take the site down"
path, backend isolation and zero-regression-risk on CSF beat DRY.)

**Consumers updated:** `score.sh`'s `_swatter_execute_block` calls
`swatter_block_direct_{perm,temp}`; `bin/swatter`'s `cmd_unblock` calls
`swatter_block_direct_unblock`. The classify / allowlist / fail-closed /
circuit-breaker logic *above* the backend is untouched — the seam is purely at
firewall execution.

### A.2 ipset backend — `lib/block_ipset.sh`

Two timeout-capable sets, one DROP rule each:
- `swatter_ipset_setup` (idempotent): `ipset create swatter4 hash:ip family inet
  timeout 0 -exist` and `swatter6 … family inet6 …`; then `iptables -C INPUT -m
  set --match-set swatter4 src -j DROP || iptables -I INPUT …` (and `ip6tables`
  for `swatter6`). Re-runnable safely.
- `swatter_ipset_temp <ip> <ttl> <reason>` — honors dry-run, the per-run cap
  (`MAX_CSF_DENIES_PER_RUN`, with its own `SWATTER_IPSET_DENIES_THIS_RUN`
  counter), and `SWATTER_HAVE_IPSET`. Picks the set by `[[ ip == *:* ]]`:
  `ipset add <set> <ip> timeout <ttl> -exist`.
- `swatter_ipset_perm <ip> <reason>` — `ipset add <set> <ip> timeout 0 -exist`
  (timeout 0 = no expiry = permanent).
- `swatter_ipset_unblock <ip>` — `ipset del swatter4 <ip>` + `ipset del swatter6
  <ip>` (`-exist`-safe).

**Persistence.** ipset sets are in-memory. After any perm add (and on unblock),
write `ipset save > ${IPSET_SAVE_FILE:-/etc/swatter/ipset.save}`. The installer
documents loading it at boot (`ipset restore < /etc/swatter/ipset.save`, e.g. via
a systemd unit or `netfilter-persistent`). Temp blocks rely on the kernel
timeout and are intentionally not persisted (a reboot clears stale temps —
correct).

### A.3 Wiring
- `lib/common.sh`: `SWATTER_HAVE_IPSET` probe (`have ipset && have iptables`);
  `DIRECT_BACKEND` default `csf`; `IPSET_SAVE_FILE` default.
- `bin/swatter`: new `setup-ipset` subcommand → `swatter_ipset_setup`; source
  `block.sh` + `block_ipset.sh`. Installer runs `setup-ipset` when
  `DIRECT_BACKEND=ipset`.
- `test-config`: report the active backend and, for ipset, whether the sets +
  rules + save-file are present.

## Part B — Multi-channel ops-critical alerts

### B.1 Shared mailer — `lib/mailer.sh` (extracted from `report.sh`)

`report.sh`'s `_report_send_{sendmail,sendgrid,brevo}` (recipient hardcoded to
`REPORT_EMAIL`) move into a shared, recipient-parameterized sender:

```
swatter_send_email <to> <subject> <body> [html]   # dispatch on REPORT_METHOD
```

`report.sh` is refactored to call `swatter_send_email "$REPORT_EMAIL" …` (a
targeted change — the send *bodies* move verbatim, only the recipient becomes a
parameter; the digest's compose/format logic is untouched). Reuses
`REPORT_METHOD`, `REPORT_FROM`, `REPORT_FROM_NAME`, `SENDGRID_KEY_FILE`,
`BREVO_KEY_FILE`/`BREVO_API_KEY`. The existing `report.sh` test continues to
guard the digest path.

### B.2 Alert dispatcher — `lib/notify.sh`

`swatter_notify <subject> <body>` fans out to **every configured channel**, each
**best-effort and independent** (a failing channel logs and returns; it never
aborts the scan or the other channels). The old `swatter_notify` in `score.sh`
is removed; `score.sh` sources `notify.sh`.

| Channel | Fires when | Mechanism |
|---|---|---|
| Local mail | `NOTIFY_EMAIL` set + `mail` present | pipe to `mail` (existing behavior) |
| SendGrid email | `ALERT_EMAIL` set | `swatter_send_email "$ALERT_EMAIL" …` (shared mailer; honors `REPORT_METHOD`) |
| Twilio SMS | `ALERT_SMS_TO` + `TWILIO_SID` + `TWILIO_FROM` + `TWILIO_TOKEN_FILE` | `POST /2010-04-01/Accounts/<SID>/Messages.json`, Basic auth `SID:token`, short body (subject + one line) |
| Webhook | `ALERT_WEBHOOK_URL` set | `POST` JSON per `ALERT_WEBHOOK_FORMAT` (auto→slack/discord/generic by URL host) |

Webhook payloads: slack `{"text":"…"}`, discord `{"content":"…"}`, generic
`{"host":…,"subject":…,"body":…}`. `auto` picks slack for `hooks.slack.com`,
discord for a `discord.com/api/webhooks` URL, else generic.

### B.3 Events (ops-critical only)
- **Circuit-breaker trip** — existing call site (`score.sh:~219`), now
  multi-channel.
- **Fail-closed engaged** — currently only `log_warn` when the allowlist is
  unhealthy in enforce mode (`score.sh:~64`); add a `swatter_notify` call there
  ("CSF/direct denies disabled — CF range list stale/missing"). This is the most
  site-safety-relevant event and the reason SMS exists.

SMS fires on the **same** ops-critical events (rare, high-signal). No per-block
alerts.

### B.4 Credentials & public docs
`SENDGRID_KEY_FILE` (exists) and new `TWILIO_TOKEN_FILE`, root-only `0600`, never
committed. A README **"Alerting"** section mirrors the "Getting your own provider
API keys" table — each channel optional, where to sign up (SendGrid, Twilio,
Slack/Discord), which var/file to set — led by **"Swatter needs no alerting
config to run."** No operator's account details appear in the repo.

## Part C — AbuseIPDB reporting (opt-in) + fleet sync

### C.1 Outbound reporting — `lib/report_abuseipdb.sh`

`swatter_abuseipdb_report <ip> <evidence_json> <reason>` — **gated on
`ABUSEIPDB_REPORT="true"` AND `ABUSEIPDB_KEY` AND curl** (off by default even
with a key, because it publishes data externally). Called from
`_swatter_execute_block` after any **confirmed** block (`did=1`), on either plane
(the logged IP is the real visitor IP via `CF-Connecting-IP`, so a via-CF
offender is equally reportable). Fully best-effort: a failure never affects the
block or the scan.

- **Dedup:** skip if `$STATE_DIR/reported/<ip>` was touched within
  `ABUSEIPDB_REPORT_TTL` (default 900s); touch it on report. Respects AbuseIPDB's
  report rate limits.
- **Category mapping** (from `decisive_rule` / `badpath_cat` in the evidence) to
  AbuseIPDB category codes:
  - `honeypot` → `21,19` (Web App Attack, Bad Web Bot)
  - `high_badpath_repeat` (credential brute) → `18,21` (Brute-Force, Web App Attack)
  - `critical_badpath` / `scanner_profile` → `21,14` (Web App Attack, Port Scan)
  - `request_flood` → `4` (DDoS Attack)
  - default → `21` (Web App Attack)
- `POST https://api.abuseipdb.com/api/v2/report` with `ip`, `categories`,
  `comment` (a short, non-sensitive offense summary — no log contents/PII).
- Config: `ABUSEIPDB_REPORT="false"`, `ABUSEIPDB_REPORT_TTL=900`.

### C.2 Fleet ban-sync — export/import files

- `swatter export-bans [file]` — emit the permanent-ban list (`offenders WHERE
  perm=1`) one IP per line to `file` (or stdout). Source of truth is the store.
- `swatter import-bans <file>` — for each IP: validate; **skip if never-block**
  (allowlist/operator/CF range/monitoring); otherwise `swatter_block_direct_perm`
  + `swatter_store_record … perm`. Honors dry-run (report mode logs intended
  imports without acting). Operator wires transport (rsync/scp/cron) between
  boxes.

## Cross-cutting

### Configuration summary (all new keys; safe defaults)
```sh
# direct-plane backend
DIRECT_BACKEND="csf"                 # csf | ipset
IPSET_SAVE_FILE="/etc/swatter/ipset.save"

# multi-channel alerts (all optional; each fires independently, best-effort)
ALERT_EMAIL=""                       # SendGrid/sendmail recipient (uses REPORT_METHOD)
ALERT_SMS_TO=""                      # Twilio destination number (E.164)
TWILIO_SID=""
TWILIO_FROM=""                       # Twilio sender number (E.164)
TWILIO_TOKEN_FILE=""                 # root-only 0600 file holding the auth token
ALERT_WEBHOOK_URL=""
ALERT_WEBHOOK_FORMAT="auto"          # auto | slack | discord | generic

# outbound reporting (opt-in)
ABUSEIPDB_REPORT="false"
ABUSEIPDB_REPORT_TTL=900
```

### New commands
`setup-ipset` · `export-bans [file]` · `import-bans <file>`.

### Files
**New:** `lib/block.sh` (router), `lib/block_ipset.sh`, `lib/notify.sh`,
`lib/mailer.sh`, `lib/report_abuseipdb.sh`.
**Modified:** `lib/score.sh` (call `swatter_block_direct_*`; source notify; add
fail-closed alert; call AbuseIPDB report after a confirmed block), `lib/report.sh`
(use `swatter_send_email`), `bin/swatter` (source new libs; `setup-ipset`/
`export-bans`/`import-bans`; `test-config` backend readiness; `SWATTER_VERSION=2.0.0`),
`lib/common.sh` (`SWATTER_HAVE_IPSET` probe + new defaults), `config/swatter.example.conf`,
`README.md`, `install/install.sh` (ipset setup when selected; document persistence).
**`lib/block_csf.sh` is NOT modified.**

### Testing
Plain bash suites, mocking `ipset`/`iptables`/`curl`/`mail`:
- **block router:** `DIRECT_BACKEND` routes temp/perm/unblock to the right
  backend (stub `swatter_csf_*` / `swatter_ipset_*`); default is csf.
- **ipset backend:** temp → `add … timeout <ttl>`; perm → `timeout 0`; unblock →
  `del` both sets; v4/v6 set selection; dry-run no-ops; cap enforced; setup
  idempotent (`-exist` / `-C` guards); save-file written on perm.
- **mailer:** `swatter_send_email` dispatches sendmail/sendgrid/brevo with the
  passed recipient; the existing `report.sh` path still sends (digest test green).
- **notify:** each channel fires only when configured; a failing channel doesn't
  abort the others; SMS body is short; webhook payload matches slack/discord/
  generic; fail-closed event triggers a notify.
- **abuseipdb report:** off without `ABUSEIPDB_REPORT=true` (no POST); category
  mapping per decisive rule; dedup (second call within TTL skips); best-effort on
  curl failure.
- **export/import:** round-trip; import skips a never-block IP; import honors
  dry-run.

### Build order
1. `lib/block.sh` router + wire `score.sh`/`cmd_unblock` (csf still default → behavior unchanged).
2. `lib/block_ipset.sh` + `setup-ipset` + `SWATTER_HAVE_IPSET`.
3. `lib/mailer.sh` extraction + `report.sh` refactor.
4. `lib/notify.sh` multi-channel + fail-closed event wiring.
5. `lib/report_abuseipdb.sh` + report-after-block call.
6. `export-bans` / `import-bans`.
7. config defaults + `test-config` readiness + example conf + README + `SWATTER_VERSION=2.0.0`.

Steps 1–2 are the backend; 3–4 the alerts; 5–6 the feedback; each is largely
independent. Per the release rule, the `v2.0.0` tag + GitHub/GitLab release is a
separate deliberate step after merge (and is the first tagged release since
`v1.2.2`, so its notes cover the v1.3 + v1.4 + v2.0 feature sets).
