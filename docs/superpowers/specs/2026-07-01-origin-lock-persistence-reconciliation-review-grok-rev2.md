## Blockers

- Managed csfpre hook cannot install DROP on `csf -r`: `install/install.sh:87` and the plan’s verbatim block (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:80-82`) call `swatter origin-lock apply --hook=csf` without `--yes`, but `cmd_origin_lock` aborts non-interactive DROP with return 3 (`lib/origin_lock.sh:477-492`), and `|| true` swallows it — so after Task 3 Step 5 retires the static block, every reload installs zero managed rules and the origin is open below CSF’s blanket accepts; `test/origin_lock_test.sh:135-142` proves this path is intentional, not accidental.
- Same path is a silent no-op when `SWATTER_MODE` is not `enforce`: `swatter_origin_lock_apply` dry-runs when `SWATTER_MODE` defaults to `report` (`lib/origin_lock.sh:296-302`, `lib/common.sh:39`, `config/swatter.example.conf:12`); Task 3 arms `ORIGIN_LOCK=drop` (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:72`) but never requires or verifies `SWATTER_MODE="enforce"` in `/etc/swatter/swatter.conf`, so Step 4 can false-pass on static-only rules while the managed hook does nothing.
- `_ol_retire_legacy_static` is spec-only, not in the tree: Task 1 (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:39-52`) and prod Step 5 (`:86`) depend on it, but `install/install.sh:53-100` only rewrites the managed marker block — no retire helper, no `test/install_origin_lock_test.sh` — and “never run `install.sh` remotely” (`:16`) leaves no documented prod invocation path.
- Retire heuristic is unsafe for partial comment-out: the plan matches individual lines (`cf_origin4`, `ORIGIN-LOCK`, `--match-set cf_origin`, or `-j DROP` on `80,443`) outside markers (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:45`) and will miss `MODE=`, `ipset create/flush/add` loops, v6-only variants, and non-matching LOG lines (`10/min` vs lib `5/min`) while still commenting some ACCEPT/DROP lines — leaving a half-live static block or, if control-flow lines are hit, a syntactically broken `csfpre.sh` (`if`/`for` with commented body lines but dangling `then`/`do`); no block-aware retire, no fixture test against the live 56-line static script.
- Fail-open integrity of the managed hook is violated on partial emit: `_ol_append` and `_ol_build_set` swallow all errors (`lib/origin_lock.sh:103-107`, `112-114`, `154-157`); if CF-ACCEPT insert fails but DROP succeeds, csfpre leaves DROP-without-CF-ACCEPT on a freshly flushed chain — the opposite of the guarded-block guarantee (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:18`, `install/install.sh:47-52`).
- `csf -r` flush + `_ol_ranges_healthy` failure installs nothing on an empty chain: gate returns 1 after CSF has already flushed INPUT (`lib/origin_lock.sh:311-314`, `326-328` skips teardown because the flush already removed rules) — fail-open by design, but post-migration there is no static fallback and every unhealthy/missing `cloudflare.cidr` reload exposes the origin until manual fix.
- LOG trailing-space teardown is still unproven on real iptables-legacy: Task 3 Step 2 (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:71`) is procedural only; `test/origin_lock_transition_test.sh` models ordering but never exercises quoted `--log-prefix "ORIGIN-LOCK: "` `-D` (`lib/origin_lock.sh:217-220`), so `disable`/off-teardown on prod remains a measured gamble until Step 2 passes.
- Rev-1 blockers are dispositioned in prose, not cleared in tree: Task 2 digest still greps `^MODE=` first (`lib/origin_lock.sh:587-588`); Task 1 retire and Task 3 Step 2 LOG gate are unchecked prerequisites (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:54-64`, `102-104`); Rev-1’s `--yes` gap was fixed for systemd in Rev 1’s recommendation but **reintroduced** on the csfpre hook in Rev 2.

## Majors

- Duplicate-owner window (Task 3 Steps 3–5) is a verification trap: plan expects “duplicate-but-harmless” rules (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:85`) while static (LOG `10/min`, inline `-I`/`-A`) and managed (`5/min`, `-A` append at `lib/origin_lock.sh:156`) stack unlike rules; Step 4 verification can pass on static-only enforcement and not catch that managed DROP never armed — Step 5 retirement then removes the only working enforcer.
- Managed-block placement in `csfpre.sh` is unspecified: `install/install.sh:69-90` appends the managed block at EOF; Task 3 Step 3 says “add the managed block” (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:72`) without requiring it after the hand static block — execution order in csfpre determines whether static `-I` prepends land above or below managed `-A` appends, changing first-match semantics relative to ground-truth `#16–#19` (`:28`).
- `--hook=csf` ordering is call-stream-tested only: `origin_lock_test.sh:58-73` records `-A` emission order but `origin_lock_transition_test.sh:116-124` exercises standalone teardown-first only; no harness models flushed-chain effective order with coexistent static-then-managed execution or post-retire single-owner verification.
- Digest `OL_MODE` still reads stale `^MODE=` from csfpre first (`lib/origin_lock.sh:587-588`); Task 2 is unchecked (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:54-64`) — reports will show wrong/empty mode after static retire.
- Rollback is csfpre-backup-only and incomplete: restoring `csfpre.sh.bak-<UTC>` (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:21`, `:87`) does not revert the Task 3 Step 1 lib deploy (`:70`) or `ORIGIN_LOCK=drop` in `swatter.conf`; a bad lib + restored hook can still break enforcement on next `csf -r`; backup taken before Step 3 may include only static (good) but backup after Step 3 arms managed includes both owners (also good for rollback).
- Reboot path is untested: survival matrix covers `csf -r`, `csf -ra`, and `lfd` restart (`docs/superpowers/plans/2026-07-01-origin-lock-persistence-reconciliation.md:26-27`) but not cold boot — CSF/csfpre ordering at boot is assumed, not measured; boot window before CSF starts may leave origin reachable.
- Prod wiring mechanism remains manual: “never run `install.sh` remotely” (`:16`) plus “add managed block” (`:72`) with no scripted/idempotent prod helper beyond hand edit — drift risk vs `install/install.sh:53-100`.
- No post-apply chain verification in code: `swatter_origin_lock_apply` logs success after blind inserts (`lib/origin_lock.sh:352-356`) with no `-C`/`-L` order assert — prod relies on manual `iptables -L` in Step 4/6.
